## 1. 문제 인식

처음에는 소리 크기로 빨강·노랑·초록을 켜는 '소음 신호등'을 만들려고 했다. 하지만 소리만 크다고 공부에 방해가 되는 것은 아니다. 환풍기 같은 백색소음은 오히려 집중을 돕기도 하고, 공기·조명·온습도도 학습에 함께 영향을 준다. 실제로 데이터과학 수업 때 7반 교실 공기를 측정해 보니, 수업·자습 시간의 절반 이상이 학교보건법 CO₂ 기준(1000ppm)을 넘었다. 소리 외의 요인도 무시할 수 없다는 뜻이다.

기존 소음 신호등처럼 센서 하나에 고정된 기준값 하나를 정해 두면, 상황과 사람에 상관없이 같은 판단을 하게 되어 오판이 생긴다. 그래서 다음을 탐구 질문으로 정했다.

> **여러 센서 값과 소리의 종류(주파수)를 함께 학습한 인공신경망이, 고정 기준값 규칙보다 교실의 학습 상태를 더 정확하게 판단하고 미리 대응할 수 있을까?**

'미리 대응'은 학습 환경이 나빠지기 전에 알려 주는 기능이다. 이 장치에서는 공기가 탁해지기 전에 환기를 알리는 기능으로 구현했다.

## 2. 탐구 설계

### 2-1. 장치

| 구성 | 부품 | 역할 |
|---|---|---|
| 제어 | ESP32 (와이파이) | 측정, 판단, 업로드 |
| CO₂ | MH-Z19C | UART와 PWM 두 방식으로 동시 측정 |
| 소리 | MAX4466 마이크 | 8kHz 샘플링, 크기·급증 횟수·**FFT 주파수 특징** |
| 온습도 / 조도 | SHT31 / BH1750 | 실내 환경 |
| 출력 | 신호등 LED, LCD, 서보모터(창문 모형) | 상태 표시, 환기 알림 |
| 클라우드 | Firebase + 깃허브 페이지 웹앱 | 실시간 확인, 라벨 기록, 원격 설정 |

장치는 **10초마다** 기록을 올리고, 최근 10분 기록으로 8가지 특징(소리 크기·변동·급증 횟수, CO₂ 평균·기울기, 조도, 온도, 습도)을 계산한다. 이 특징을 인공신경망에 넣어 **환경 부담 점수(0~1)** 하나를 구하고, 점수에 따라 신호등을 **초록(양호) → 노랑(주의) → 빨강(경고)** 3단계로 켠다. 소음·조도·CO₂를 따로따로 판단하지 않고, 모든 센서를 한꺼번에 본 신경망 계산 하나로 단계를 정하는 방식이다. 원인(CO₂ 상승, 조명 부족, 소음 등)은 LCD와 웹앱에 설명으로 따로 보여 준다.

### 2-2. 정답(라벨) 만들기

학습 중 웹앱에 집중도(1~5), 졸림(1~5), 자는 학생 수, 메모를 남겼다. 상태 규칙은 다음과 같다.
- 졸림 ≥ 4 → **졸림**
- 집중도 ≥ 4 → **최적**
- 그 외 → **산만**

라벨 하나는 직전 20분의 10초 기록 전체를 대표한다. 신경망은 이 라벨로 '최적일 확률'을 배우고, 장치는 **환경 부담 점수 = 1 − 최적 확률**로 바꿔 신호등에 쓴다.

### 3-2. 전처리 (`analysis/01_preprocess.ipynb`)

1. **예열 구간 제거:** MH-Z19C는 켠 뒤 3분 동안 불안정해 50개 기록의 CO₂를 결측 처리했다.
2. **센서 신뢰성 검증:** 같은 센서를 UART와 PWM 두 방식으로 동시에 읽어 비교했다. 8,518개 기록에서 **평균 절대 차이 0.8ppm, 상관계수 r = 1.000**으로, 통신·계산 오류가 없음을 확인했다.
3. **날숨 급등 보정:** 센서 가까이에서 말하면 CO₂가 10초 만에 약 450ppm 뛰었다가 돌아왔다. 방 공기가 아니라 숨이 직접 닿은 것이므로, 주변 2분 중앙값보다 250ppm 이상 높은 기록 15개를 중앙값으로 바꿨다.
4. **교실 데이터 순간 튐 제거:** 1~2분 동안 400ppm 근처로 떨어졌다 돌아오는 측정 오류 25분을 제거했다.
5. **측정 공백·빈 방 구간:** 기록 간격이 60초를 넘으면 구간을 나눴다. 외출 시간(11/14 17:00~21:20)은 '빈 방'으로 표시했다.
6. **장치와 같은 특징 계산:** 학습한 모델을 장치에 그대로 넣으려면 입력 계산식이 같아야 한다. 그래서 펌웨어와 똑같은 식(최근 60개 기록의 평균·합·최소제곱 기울기)으로 10분 특징을 계산했다.
7. **z-점수 표준화:** 단위가 다른 특징(ppm, lx, ℃)을 평균 0, 표준편차 1로 맞췄다.

## 4. AI 모델 학습 · 예측 결과 분석 (평가 ②)

### 4-1. 학습 상태 분류 인공신경망 (`03_state_classifier.ipynb`)

**평가 방법:** 라벨 구간 하나를 통째로 빼서 평가하는 교차검증(9번)을 썼다.

| 방법 | 특징 | 정확도 | macro F1 | 라벨 단위 정확도 |
|---|---|---|---|---|
| 기존 규칙 (장치 신호등) | – | 9.1% | 0.12 | – |
| k-NN | 기본 8개 | 40.3% | 0.37 | 44.4% |
| 결정 트리 | 기본 8개 | 37.4% | 0.37 | 44.4% |
| 로지스틱 회귀 | 기본 8개 | 53.2% | 0.53 | 55.6% |
| 인공신경망 MLP | 기본 8개 | 53.9% | 0.54 | 55.6% |
| **인공신경망 MLP** | **기본 + 주파수 11개** | **56.4%** | **0.56** | **66.7%** |

**분석**
- **기존 규칙의 오판:** 측정 중 CO₂가 1500~2400ppm이었다. 규칙은 690개 기록 중 431개를 '졸림'(노랑)으로 판단했지만, 실제로 졸림 4 이상을 느낀 적은 한 번도 없었다. 사람과 상황에 상관없이 하나의 고정 임계값을 쓰는 규칙의 한계다.
- **인공신경망:** 실제 라벨로 학습하자 정확도가 9.1%에서 53.9%로 올랐다. **주파수 특징을 더하면** 56.4%, 라벨 단위로는 66.7%가 되어 모든 모델 중 가장 높았다.
- **특징 중요도:** 온도, CO₂, 습도, 스펙트럼 중심 순으로 중요했다. 다만 측정 2시간 동안 CO₂와 온도가 함께 오르며 시간과 얽혀 있어, 온도의 중요도는 '시간 흐름'의 영향이 섞인 값으로 해석해야 한다.

|---|---|---|---|

### 4-3. 미리 대응하기 — 환기 알림용 CO₂ 예측 인공신경망 (`02_co2_forecast.ipynb`)

조절기는 공기가 탁해지기 *전에* 환기를 알려야 한다. 기존 펌웨어는 최근 기울기를 직선으로 이어 도달 시간을 계산했는데, 이를 인공신경망으로 개선할 수 있는지 확인했다.

**문제 설정:** 1·2·5·10분 동안의 CO₂ 변화량과 창문 열림 정도를 입력으로, **10분 뒤 CO₂ 변화량**을 예측한다. 정답이 '10분 뒤 실제 측정값'이라 사람이 라벨을 달 필요가 없어서, 교실 5일과 집 하루 기록을 모두(5,551개 시점) 학습에 썼다.

**평가 방법:** 하루를 통째로 빼서 평가하고 나머지 날로 학습하는 것을 7일 모두 반복했다. 무작위로 섞으면 1분 차이 나는 거의 같은 기록이 학습과 평가에 함께 들어가 성능이 부풀려지기 때문이다.

**선형회귀 손계산**
- 손실함수: L(w, b) = (1/n) Σ (yᵢ − xᵢᵀw − b)²
- 편미분: ∂L/∂w = −(2/n) Xᵀ(y − Xw − b)
- 헤시안: H = (2/n) X̃ᵀX̃ 는 w와 상관없이 일정하다. 고윳값이 모두 양수(0.164 ~ 6.215)이므로 L은 볼록함수이고, 극소점이 곧 유일한 최소점이다.
- 학습률 조건: 경사하강의 오차에는 매 단계 (I − ηH)가 곱해진다. 따라서 |1 − ηλ| < 1, 즉 **η < 2/λmax = 0.322**여야 수렴한다.
- 확인: η = 1/λmax로는 수렴했고, 정규방정식의 해와 소수 둘째 자리까지 같았다. η = 2.05/λmax로는 실제로 발산했다 (`02_gd_learning_rate.png`).

**결과**

| 방법 | 전체 MAE | CO₂ 상승 중 MAE |
|---|---|---|
| 그대로 유지 | 113.0 ppm | 242.5 ppm |
| 직선 연장 (기존 펌웨어) | 134.6 ppm | 240.4 ppm |
| 선형회귀 (경사하강) | 108.0 ppm | 224.2 ppm |
| **인공신경망 MLP (16, 8)** | **107.1 ppm** | **213.9 ppm** |

- 환기 알림이 필요한 'CO₂ 상승 중' 상황에서 MLP 오차가 가장 작았다. 기존 펌웨어 방식보다 **11%** 작다.
- "10분 안에 2000ppm을 넘는다"는 알림으로 써 보면, MLP는 **정밀도 0.88**로 헛알림이 거의 없지만 재현율이 0.28이다. 기존 방식은 재현율 0.42, 정밀도 0.62였다.
- 그래서 두 방식 중 **하나라도 넘으면 알리는 조합**이 적절하다고 판단했다.
- 10분 안의 큰 변화는 대부분 창문을 열거나 사람이 드나드는 *사람의 행동* 때문이다. 센서 값만으로는 미리 알 수 없다는 것이 예측의 본질적인 한계다.

### 4-4. 생성형 AI를 활용한 최적 조건 탐색 결과

(근거: 7반 교실 실측, 창문을 연 사건 82번 분석, 상태 분류 MLP의 '최적' 확률 지도, CO₂ 예측 모델 평가)

| 설정 | 값 | 근거 |
|---|---|---|

| 환기 해제 | **1000 ppm** | 학교보건법 기준이자 야간 자율학습 평균 수준 |

| 환기할 창문 | **3개 이상** | 1~2개는 10분 동안 오히려 증가(+1.7, +3.7ppm/분), 3개 이상만 평균 **46ppm/분** 감소 |

- 1교시 전에 창문 3개 이상 열기

- 야간 자율학습은 장치 알림이 있을 때만 환기

## 5. 모델 구현 및 오류 수정 (평가 ③)

### 5-1. 인공신경망을 ESP32에 탑재 — 환경 부담 점수로 신호등 켜기 (`05_export_to_esp32.ipynb`)
- 학습한 MLP(8 → 16 → 8 → 3)의 가중치를 C 헤더 `model_weights.h`(4.4KB)로 변환했다.
- 펌웨어에 z-점수 → 행렬곱 → ReLU → 소프트맥스 계산을 직접 구현했다. 장치가 직접 **환경 부담 점수 = 1 − P(최적)**를 계산한다.
- **3단계 판단:** 점수를 10초마다 5%씩 따라가는 지수이동평균(약 3분 평균 효과)으로 부드럽게 한 뒤 단계를 정한다.
  - 0.4 미만 → 초록(양호)
  - 0.4 이상 → 노랑(주의)
  - 0.7 이상 → 빨강(경고)
  - 두 기준은 웹앱에서 바꿀 수 있다.
  - 안전장치: 아주 시끄러울 때는 0.3초 안에 즉시 빨강, 환기 알림 중에는 최소 노랑을 켠다.
- **평가 (학습에 쓰지 않은 라벨 구간):**
  - 부드럽게 하자 점수의 구분력(AUC)이 0.686에서 **0.715**로 올랐다.
  - 실제 '산만'일 때는 빨강이 52%, 실제 '최적'일 때는 초록이 61%로 가장 많았다 (`05_score_levels.png`).
- **검증:** 장치와 같은 32비트 실수로 다시 계산했다. 690개 기록에서 예측이 **100% 같았고**, 점수 차이는 최대 0.0000002였다.

## 6. 결론과 한계

**결론**
- 여러 센서와 소리의 주파수 특징을 함께 학습한 인공신경망이 **고정 기준값 규칙보다 실제 학습 상태를 훨씬 잘 판단**했다 (정확도 9.1% → 56.4%).
- 센서마다 따로 기준을 두는 대신, 신경망이 계산한 **환경 부담 점수 하나로 신호등 3단계**를 정하도록 장치를 바꿨다. 장치 계산이 파이썬 모델과 같음을 검증했다.
- 소리의 종류(말소리·백색소음 등)를 주파수로 구분하자 판단이 더 정확해졌다. 소리 크기만 보던 소음 신호등의 한계를 넘었다.
- 미리 대응하는 기능으로, CO₂ 예측 인공신경망이 공기가 탁해지는 상황에서 기존 방식보다 오차가 11% 작고 헛알림이 적었다.
- 실측과 생성형 AI 분석으로 장치 설정값(졸음 임계값 2000ppm, 창문 3개 이상 환기)을 정했다.

**한계와 개선 방향**
1. **상태 라벨이 적다.** 한 명이 약 2시간 동안 남긴 라벨 9개라 '졸림'은 학습하지 못했고, 개인차도 반영되지 않았다. 신호등을 점수 기반 3단계로 바꿔 이 문제를 일부 피했지만, 점수의 구분력(AUC 0.715)도 아직 높지 않다. 여러 학생이 여러 날 라벨을 남기면 노랑·빨강 기준도 데이터로 다시 정할 수 있다.
2. **CO₂ 급변은 사람의 행동 때문이다.** 창문 개폐 센서(리드 스위치)를 장치에 연결하면 예측에 바로 쓸 수 있다.
3. **마이크 한계:** 큰 소리에서 파형이 잘리는 경우가 1.1% 있었다. 디지털(I2S) 마이크로 바꾸면 주파수 특징이 더 정확해진다.
